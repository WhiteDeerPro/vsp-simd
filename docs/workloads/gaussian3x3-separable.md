# 可分离 3×3 Gaussian 与两次舍入代价 `[工作负载证据；比较集合]`

## 1. 目的

[单通道 3×3 Gaussian](gaussian3x3.md) 第 7 节把可分离 Gaussian 列为受阻项：拆成两个
`[1,2,1]` pass 能把每输出的 tap 数从九降到六，但水平中间值最大 1020 需要 10 bit，
8-bit VRF 无法无损保存，而 `MUL/MAC` 是 byte-only。

本负载实现今天**唯一可闭合**的方案——每个 pass 都缩回 8 bit，接受两次舍入——并测量
它的两项代价：数值偏差和微操作计量。目的是给「是否值得增加 HALF 中间值支持」提供
可比较的数字，而不是主张可分离映射更好。

## 2. 映射

两个 pass 各四条微操作，都不会饱和（`4 × 255 = 1020`，`(1020+2)>>2 = 255`）：

```text
pass 1（水平）  h = (p[x-1] + 2·p[x] + p[x+1] + 2) >> 2
pass 2（垂直）  out = (h[y-1] + 2·h[y] + h[y+1] + 2) >> 2
```

| 次序 | pass 1 | pass 2 |
|---:|---|---|
| 1 | `MUL_U imm=1`，`SLIDE_UP(1)` → `a0` | `MUL_U imm=1`，行 `y-1` → `a0` |
| 2 | `MAC_U imm=2`，无 route | `MAC_U imm=2`，行 `y` |
| 3 | `MAC_U imm=1`，`SLIDE_DOWN(1)` | `MAC_U imm=1`，行 `y+1` |
| 4 | `NCLIP_U imm=2` → VRF | `NCLIP_U imm=2` → VRF |

pass 2 **完全不需要 route**：垂直邻居是不同的行，各自装载到独立 VRF row。这与 Sobel
形成对照——Sobel 27% 的微操作是为了绕开「route 只作用于 source A」而做的数据搬运。

## 3. 数值代价 `[实测]`

偏差是与精确九 tap 单次舍入 `(Σw·p + 8) >> 4` 的逐像素差。按内容分类，因为平滑滤波
的舍入误差几乎完全由空间内容决定：

| 图样 | 最大偏差 | 平均偏差 | 有偏差像素 |
|---|---:|---:|---:|
| 均匀 | 0 | 0 | 0% |
| 水平 ramp | 0 | 0 | 0% |
| step edge（三方向） | 0 | 0 | 0% |
| 棋盘（周期 1/2/4） | 0 | 0 | 0% |
| 单点脉冲 | 0 | 0 | 0% |
| zone plate | 1 | 0.083 | 8.3% |
| 均匀噪声（40 张） | 1 | 0.216 | 21.6% |
| 随机尺寸噪声（120 张） | 1 | 0.220 | 22.0% |

一个不显然的结果：**二值与 step 内容下两 pass 与九 tap 精确相等**。周期 1 的棋盘经
水平 pass 后整幅变成均匀的 128，精确九 tap 也给 128；0/255 这类取值使 `/4` 恰好落在
整数上，双重舍入不产生误差。偏差只在中间调内容上出现，最坏情况（均匀噪声）是 22%
的像素差 1 LSB，平均 0.22 LSB。最大偏差在全部输入域内为 1；测试断言的界是 2，属于
故意放宽的实测界，不是解析证明。

结论：两次舍入的代价是 **≤1 LSB，且只在中间调内容上出现**。对 8-bit 进 8-bit 出的
平滑滤波，这不构成需要 HALF 中间值的理由。

## 4. 微操作代价 `[需要中间行复用]`

关键前提是 pass 1 的结果必须被**三个垂直窗口复用**：

| 组织方式 | 每 4 输出像素微操作 | 说明 |
|---|---:|---|
| 直接九 tap | 10 | 见 [gaussian3x3.md](gaussian3x3.md) |
| 可分离 + 中间行复用 | 8 | 4（水平，每输入行一次）+ 4（垂直） |
| 可分离 + 无复用 | 16 | 每输出行重算三次水平 pass = 12 + 4 |

也就是说可分离只在有 line buffer 时才赢，赢 20%；没有复用时它比直接映射慢 60%。
本测试把水平中间值整幅保存在驱动侧，**代表硬件尚不存在的存储**——当前没有本地
SRAM、DMA 或行缓冲 RTL，所以这 20% 不是已可兑现的收益，而是对存储层的需求陈述。

## 5. 对 HALF 支持的判断

综合第 3、4 节，可分离 Gaussian **不构成**增加 HALF `MUL/MAC` 的理由：数值代价
≤1 LSB，而指令收益取决于一个尚不存在的行缓冲。

无损单次舍入版本需要把 10-bit 中间值保存下来，路径是 HALF 粒度的 `ACC→VRF` 导出
（`NCLIP`/`NSLICE` 出 16-bit 元素）加上 HALF `MUL/MAC`。当前 `ACC→VRF` 只有「每 lane
一个 byte」，重组一个跨 lane 的 HALF 元素需要 byte 级转置，代价见
[sobel3x3.md](sobel3x3.md) 第 2 节。因此 HALF 支持的驱动力应来自真正需要
>8-bit **输出**或多级级联的负载，而不是这个两级 8-bit 滤波。

现有 BYTE/HALF/WORD 支持范围见[数据通路](../architecture/datapath.md)与
`simd_op_mode_legal`。

## 6. 验证

`sim/gaussian3x3_separable_tb.cpp` 在 `simd_datapath` 上执行两个 pass，并使用两个彼此
独立的 C++ 模型：

- **oracle 1**：同为两次舍入的可分离算术，作为正确性 oracle（RTL 是否正确实现该映射）；
- **oracle 2**：精确九 tap 单次舍入，作为精度标尺（该映射偏离理想结果多少）。

RTL 只执行可分离映射；九 tap 直接映射的数值覆盖仍由 `gaussian3x3_tb` 负责，本测试
不重复。

图样为程序化生成，不引入任何二进制资源或网络依赖：均匀、ramp、三方向 step edge、
周期 1/2/4 棋盘、单点脉冲、zone plate（平方半径三角波，各向不对齐）、均匀噪声，以及
120 张随机尺寸噪声图覆盖 tail mask、单 lane 宽度和图像边界。

测试自带覆盖自证：若整轮偏差恒为零，或中间调内容没有产生偏差，测试直接失败——避免
比较退化成恒等式。

```bash
make test
```

### 手动查看真实图片

回归不读取外部图片，但可以手动传入一张 8-bit binary PGM（P5，支持注释行）。测试会
运行两条路径并写出两张 PGM 供肉眼比较，同时报告偏差：

```bash
$(BUILD_DIR)/gaussian_separable_obj_dir/Vsimd_datapath 输入.pgm
# 产生 输入.pgm.separable.pgm 与 输入.pgm.exact.pgm
```

这条路径不进入 `make test`，因此仓库不携带图片，回归也不依赖网络。
